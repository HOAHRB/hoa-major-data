# hoa-major-data

本仓库存放哈尔滨工业大学本部的培养方案数据。

## 数据范围

当前收录 2023—2026 级本科培养方案，其他类别保留已有的 2024—2026 级数据。

## 我们如何组织课程与资料

学生在培养方案中看到的是一门门具体的课，而资料站还要回答：哪些课适合共用一份文档？
哪些独立文档值得一起参考？学习这些内容时，有没有明确的先后顺序？
我们用**实体课程、宏课程、课程群和课程系列**分别表达这些关系。

| 概念 | 表达的关系 | 例子 |
| --- | --- | --- |
| 实体课程 | 某个专业、某个年级培养方案中的具体课程记录 | 某专业 2025 级方案中的“计算思维与人工智能” |
| 宏课程 | 多门实体课程共同维护文档与资料的入口，由文档映射落实 | 计算思维与信息基础、计算思维与人工智能等共用“计算思维”文档 |
| 课程群 | 多个独立宏课程之间值得相互参照的内容或资料关联，没有先后顺序 | 分别维护资料、但存在具体内容联系的课程可以加入同一群 |
| 课程系列 | 多个宏课程之间明确的学习顺序，只允许单链 | 微积分第一册 → 微积分第二册 |

计算思维的例子描述已有的资料归并；课程群和系列的例子用于解释概念，不表示相关关系已经录入。

是否共用宏课程，取决于实际内容、难度、考核方式和资料维护需求。共用资料后，各实体课程
仍保留本专业、本年级的原始课号、名称、学分和考核要求，不表示课程可以互相替代。
内容相关但需要独立习题或考试资料时，可以保留不同宏课程，再按需建立课程群或系列。
如果顺序发生在同一个宏课程内部，例如已合并的体育（1—6），则通过文档章节和开设学期说明，
无需为展示顺序拆分资料。

宏课程归属通过 `lookup_table.toml` 维护，展示名称复用课程仓库的文档标题；
课程群和系列的名称及成员通过独立的 `course_relations.toml` 维护。
群和系列的成员均为宏课程，支持多对多关联，但这些关系不能从文档映射自动推导。
首批关系已录入：微积分系列课程、微积分E系列课程，以及微积分（上）、微积分（下）、代数与几何三个课程群。后端生成关系数据，前端在构建时生成关系索引和本方案课程入口；具体条目见 `course_relations.toml`。

完整的设计说明、维护选择、关系文件格式与命名约定，见 [我们如何组织课程与资料](docs/course-model.md)。

## 文件维护方式

`major_mapping.json`、`plans/` 和 `course_introductions.json` 由 `hoahrb-jwts`
根据教务系统数据生成。课程介绍随 `jwts crawl` 抓取，并只覆盖本次涉及课程的条目。

培养方案文件以类别开头：`本_`、`辅修_`、`第二学士学位_`、`本科国际生_`、`微专业_`
或 `未分类_`。每个 TOML 的 `[info].plan_category` 必须与文件名前缀一致。
当前站点只发布 `本_` 培养方案，其他类别仍保存在本仓库中。

## 培养方案元信息的权威来源

每个培养方案 TOML 的 `[info]` 是该方案完整元信息的权威来源，包括：

- `year`：年级
- `major_code`：专业代码，也是同一年级内方案的唯一标识
- `major_name`：专业名称
- `school_name`：学院名称
- `plan_category`：方案类别
- `study_level`：培养层次；当前所有方案统一为 `"undergrad"`
- `plan_ID`：由 `HIT-{year}-{major_code}` 确定的方案标识

文件名和 `major_mapping.json` 均由同一份方案元信息生成，只是面向不同用途的投影，
不应作为独立来源单独修改：

- 文件名用于人工辨识和发布前过滤。它包含类别、年级、学院及通常情况下的专业名称；
  名称会经过文件系统安全清洗，学院名与专业名相同时还会省略重复的专业名，因此文件名
  不是专业名称或学院名称的无损副本。当前 Fuma 构建脚本按 `本_*.toml` 白名单发布
  普通本科方案，所以文件名前缀必须与 `[info].plan_category` 一致。
- `major_mapping.json` 以 `year` 和 `major_code` 为索引，保存 `name`、`school_name`、
  `plan_ID` 等供前端专业列表使用的展示信息。它目前不保存方案类别；其中各字段必须与
  对应 TOML 的 `[info]` 一致。

后端从 TOML 的 `[info]` 读取年级、专业代码、专业名称和 `plan_ID`，使用年级与专业代码
生成页面路径，并使用专业名称生成导航元信息。Fuma 的专业选择列表名称来自
`major_mapping.json`。因此维护数据时必须同时满足：

1. 文件名前缀与 `[info].plan_category` 一致；
2. `major_mapping.json` 中的年份、专业代码、专业名称、学院名称和 `plan_ID` 与
   对应 TOML 的 `[info]` 一致；
3. 同一年级内不得出现重复的 `major_code`，`plan_ID` 必须保持确定性和唯一性。

为兼容上游的培养层次筛选，所有方案的 `[info].study_level` 和
`major_mapping.json` 对应条目的 `study_level` 均显式设为 `"undergrad"`，两处必须一致。
本仓库目前没有研究生方案；该值是本科层次的兼容默认值，不从 `plan_category` 推导，
也不改变普通本科、辅修、第二学士学位或本科国际生等既有类别及发布范围。
`hoahrb-jwts` 抓取时输出此字段，`merge-data` 为缺少字段的旧方案补上该默认值。

以下文件由维护者手工管理，不会被 `hoahrb-jwts` 覆盖：

- `lookup_table.toml`
- `grades_summary.json`
- `shared_categories.toml`
- `course_relations.toml`：课程群及单链课程系列；宏课程名称复用资料仓库的文档标题，格式见 [课程组织模型](docs/course-model.md)

## 更新数据

先在 `hoahrb-jwts` 仓库中抓取指定年级的数据：

```powershell
uv run jwts crawl --years 2024 2025 2026 --data-dir ..\hoa-major-data
```

抓取完成后检查生成内容：

```powershell
git diff -- major_mapping.json course_introductions.json plans
```

确认新增、修改和删除均符合预期后，再提交本仓库的更改。

## 课程身份与成绩构成

实体课程、宏课程、课程群及单链课程系列的定义，以及宏课程大驼峰标识和历史迁移约束，见 [课程组织模型](docs/course-model.md)。宏课程直接由文档映射落实；课程群和课程系列不从映射关系自动推导。

专业课程路由和课号使用培养方案中的原始 `course_code`。`lookup_table.toml` 只选择正文、资料下载和 GitHub 入口使用的资源仓库，不改变课程元数据或教务简介的身份。

课程合并仅纳入 `plan_category = "本"` 且 `study_level = "undergrad"` 的普通本科主修方案，
排除辅修、第二学士学位、国际生和硕博方案；这些类别的原始数据继续保留。
课程分组以普通本科主修为筛选范围，`lookup_table.toml` 统一使用 `DEFAULT` 映射，
不设置专业或培养方案覆盖项；其他类别若共用相同课号，也会使用该课号的默认资料入口。

`09333` 经维护者于 2026-10-24 复查确认属于本科国际生，跨年级排除普通本科主修范围。
现有 2024 级方案已改用 `本科国际生_` 文件名前缀及类别，原始课程和总索引条目保留。
该方案不进入普通本科主修发布范围；共用课号的资料入口仍遵循上述 `DEFAULT` 映射规则。

`35163` 汉语言文学同日经维护者确认属于本科国际生；2023—2025 级 3 份方案均已改类，
108 条原始课程及总索引条目保留。`09333`、`35163` 的来源类别修正均使用
`hoahrb-jwts` 的 `year = "*"` 规则，后续新年级、缓存重抓和旧数据合并也自动归入
本科国际生，不再进入普通本科主修发布或合并候选。

当前主修体育（1—6）、旧体育课号及对应校区课号共用 `PhysicalEducation` 资料仓库，
这里的仓库名表示映射目标；除军事课程外，其余宏课程资料仓库尚未建立，资料仍待补充。
具体 21 个课号以 `lookup_table.toml` 为准。体育史和体育建筑设计专题保持独立。
各学期的资料应在资源仓库内标明适用范围；各培养方案中的学分、考核方式等仍分别保留。
主修范围内的全部计算思维课程共 8 个课号统一使用 `ComputationalThinking` 资料仓库，
包括计算思维与信息基础、计算思维与人工智能、计算思维与人工智能 A、
大学计算机-计算思维导论及对应校区课号。仅见于国际生方案的 `22CS14004E` 不纳入。
主修 5 学分微积分及 `22MA15` 系列全部数学分析（包括 x 和 4 学分版本）按册合并：
第一册使用 `Calculus1`，第二册使用 `Calculus2`。
4 学分微积分 E 的不同版本按册分别使用 `CalculusE1`、`CalculusE2`，包括 C 后缀和对应校区课号；
国际生版本不纳入。6 学分微积分保持原课号。
主修范围内全部 3.5 学分及 4 学分的代数与几何统一使用 `AlgebraAndGeometry`，3 学分的 F、H 版本（含对应校区、C 后缀课号）共用 `AlgebraAndGeometryFH`，P 版本保持独立。
`22MA22` 系列中，`22MA22101` 与 `22MA22001` 共用 `MathematicalAnalysis1`；
C 后缀课程按册分别使用 `MathematicalAnalysisInternational1`、`MathematicalAnalysisInternational2`、`MathematicalAnalysisInternational3`。
菁英班的 `22MA22017`、`22MA22019`、`22MA22903` 各自独立，普通第二、三册仍分别使用
`22MA22013`、`22MA22006`。

专业课程成绩构成在对应培养方案的课程条目中维护，不使用中央 `grades_summary.json` 补全：

```toml
[[courses]]
course_code = "22MA15005"
course_name = "微积分C（1）"
grade_details = [
  { name = "平时成绩", percent = "30%" },
  { name = "期末考试", percent = "70%" },
]
```

按入学年份、专业和原始课号确认适用范围，在提交说明中提供依据。缺少字段或值为 `[]` 时显示暂无成绩构成；当前数据尚未普遍提供该字段。`hoahrb-jwts` 更新培养方案时按年份、专业代码和原始课号保留已有的手工 `grade_details`，课程删除或课号变化时不自动迁移；若会丢失已有贡献，发布会报错，需先确认并迁移或归档。

`grades_summary.json` 继续保留上游以仓库 ID 为键的语义，供没有培养方案身份的共享分类页使用。课程仓库正文中的成绩徽章也属于资料正文，不作为专业课程信息栏的来源。

军事理论与军事技能（军事训练）在普通本科主修范围内统一使用 `MilitaryTraining` 资料仓库，
该仓库由原军事理论仓库 `22AD16001` 重命名而来，历史拼写 `MillitaryTraining` 已修正；培养方案中的原始课程身份分别保留。
